# KuboDeck v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** configuratore web statico del deck box Standard 60 che mostra la scatola in 3D e scarica STL manifold stampabili sulla Bambu Lab A1 Mini.

**Architecture:** funzioni pure TypeScript `config → parti manifold` (manifold-3d WASM) alimentano sia la viewport React Three Fiber sia l'export STL, così ciò che si vede è ciò che si stampa. Lo stato è un `useReducer` sincronizzato con l'URL (`v=1`). I controlli geometrici sono codice di produzione (bloccano l'export) e test Vitest.

**Tech Stack:** Next.js 16.4.6 (App Router, `output: 'export'`), React 19, TypeScript strict (la versione installata da `create-next-app@16.4.6`), CSS puro, three 0.187.0, @react-three/fiber 9.8.2, @react-three/drei 10.7.9, manifold-3d 3.5.5, opentype.js 2.0.0, fflate 0.8.3, Vitest 5.1.1 (+ jsdom 31.0.1, @testing-library/react 16.3.3 solo per i test UI).

**Spec:** `docs/superpowers/specs/2026-11-19-kubodeck-design.md`

## Global Constraints

- Unità: 1 = 1 mm. Assi: X larghezza, Y profondità (faccia frontale a `y = 0`), Z verso l'alto.
- Standard 60, quote esterne: larghezza `78`, altezza `104`, profondità `stackThicknessMm + 2 × 2.8 + cardClearanceMm`.
- Pareti `2.8`; colletto `1.2`, gioco calotta `0.30`, parete laterale calotta `1.3`; calotta alta `30`, corpo `74`, gioco verticale colletto-soffitto `0.30`; fondo e soffitto `2.8`.
- Carte con doppia bustina `67 × 93`; `stackThicknessMm` di partenza `33` è una **stima** (≈0,55 mm × 60) da tarare con la stampa; `cardClearanceMm` `1.0`.
- Rilievo fronte `+0.8`; intarsio calotta a filo profondo `0.6`; tratto minimo `0.8`.
- Piatto A1 Mini `180 × 180 × 180`, margine `5` per lato.
- Nessun magnete nella v1.
- Ogni parte esportata è manifold (`status() === 'NoError'`, non vuota) e le parti sono disgiunte.
- Viewport caricata con `next/dynamic(..., { ssr: false })` più uno skeleton; la pagina mostra subito il contenuto.
- Stile: tutto il flusso `/impeccable` (Task 7 e 10); `reference/craft-floor.md` si rilegge prima di ogni modifica alla UI. Font Plus Jakarta Sans e JetBrains Mono, indirizzo "industrial design studio".
- Ogni oggetto manifold intermedio si libera con `.delete()` in un `try/finally`, così un'eccezione non perde memoria WASM; le parti si liberano con `disposeParts`, le `BufferGeometry` con `dispose()`.
- Privacy: autore `xdelmo` con l'email noreply; niente percorsi `/Users/…`, email o token nei file committati. Commit con merge, mai rebase o squash.
- Un comando solo per la verifica: `npm run verify` = `tsc --noEmit && vitest run && next build`.

## Review Focus

1. **Caratteri che il font non ha** (accenti fuori Latin, emoji, CJK): il testo non deve diventare quadratini `.notdef` stampati. Ci si aspetta un controllo rosso che nomina il carattere. Test nel Task 4.
2. **Testo vuoto, solo spazi o troppo lungo**: vuoto vuol dire nessuna parte di testo e nessun errore; troppo lungo vuol dire controllo `artFitsFace` rosso con un messaggio. Test nel Task 4.
3. **URL manomesso o vecchio** (`v` mancante o `v=2`, numeri fuori intervallo, id sconosciuti, JSON rotto): la pagina si apre sempre con la config di default o con i campi validi recuperati, e non va mai in crash. Test nel Task 2.
4. **WASM o font che non si caricano** (rete lenta o 404): la pagina resta usabile, la viewport mostra un errore leggibile e l'export resta disabilitato. Test nel Task 8.
5. **Modifiche rapide durante una rigenerazione asincrona**: un risultato vecchio non deve sovrascrivere uno nuovo, e le parti sostituite vanno liberate. Test nel Task 8.
